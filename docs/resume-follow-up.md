# 이력서 보완을 위한 확인 사항

2026-09-08 기준. 공개 이력서에 넣을 문구가 아니라 작성자 확인용 메모입니다.
기존 원문에 적힌 경험을 바탕으로 문장을 수정했으며, 실제 성과의 독립적인 검증을 수행한 것은 아닙니다.
답변이 없는 내용은 새로 만들어 넣지 않았습니다.

## 답변을 받아 반영한 내용

- **OTA 시간**: 사용자가 앱을 실행한 후 업데이트 번들을 내려받는 시간. Android·iOS 모두 `4~5초 → 1~2초`로 개선. 배포 파이프라인 소요 시간이 아닌 사용자 다운로드 시간으로 명시했습니다.
- **서비스와 역할**: 타이어픽은 타이어 판매부터 장착 매장 연결까지 제공하는 서비스 앱. 카티니·딜러타이어에서 앱 리드를 맡았고, 영업양수도 이후에도 같은 앱의 개발·운영을 계속 담당했습니다. 팀 구성은 회사마다 달라 구체적인 인원이나 관리 범위는 추가하지 않았습니다.
- **New Architecture 대응**: 호환성 문제가 있고 버전 업데이트가 제공되지 않는 라이브러리를 제거하고, 필요한 디자인 UI 컴포넌트를 직접 구현했습니다. React Native Paper의 프로그레스바와 일부 UI 컴포넌트를 직접 구현해 대체한 경험을 추가했습니다. React Native Paper 자체의 유지보수가 중단되었다고 단정하지 않습니다.

## 다음에 보완하면 좋은 내용

- **다운로드 개선 이력**: 작성자는 두 번 나누어 작업했던 것으로 기억한다고 답했습니다. 기존 경력 분류에 따라 카티니에 `약 10초 → 3~4초`, 딜러타이어에 `4~5초 → 1~2초`를 각각 반영했습니다. 첫 수치는 평균값으로 단정하지 않았습니다. 정확한 작업 시기와 측정 기록은 추후 확인할 수 있으면 보완합니다.
- **직접 구현한 UI 검증**: 프로그레스바 외 대표 컴포넌트 이름이나 동작 검증 방법이 기억나면 기술 사례를 보강할 수 있습니다. 현재 답변만으로 가능한 수정은 반영했습니다.

## 수치와 결과 보완

- **앱 70~80MB → 50MB 이하 / 번들 30~40MB → 약 10MB**: 원문의 전후 용량은 유지했습니다. 용량 수치의 플랫폼별 기준(Android/iOS), 산출물(APK/AAB/스토어 다운로드/압축 번들 등), 비교 조건을 확인해주세요. 번들의 `70% 이상` 표현은 범위 전체에서 성립하지 않아 제거했습니다.
- **다운로드 측정 조건**: 확인된 `4~5초 → 1~2초`의 기기·네트워크·반복 측정 여부는 필요할 때 보완합니다. 평균값이나 감소율은 별도로 단정하지 않았습니다.
- **롤백 약 50% 감소**: 비교 기간, 전후 건수, 배포 횟수, 함께 수행한 안정화 작업이 무엇인가요? 확인 전까지 본문에서 제외했습니다.
- **프로젝트 착수 리소스 약 30% 절감**: 리소스는 작업 시간·인원·비용 중 무엇인가요? 전후 기준이 없으면 보일러플레이트로 공통화한 작업만 유지합니다.
- **퍼널·CVR·ROAS**: 어느 화면에서 어떤 이탈을 발견했고 무엇을 바꿨나요? 결과와 비교 조건이 있나요? 본문에는 로그 설계·분석·화면 개선 실험만 남겼습니다.
- **인프라 비용**: ECS/EC2와 S3·Lambda의 역할, 전후 월 비용이 확인되면 보강할 수 있습니다. 현재는 전환 목적과 구성만 설명합니다.
- **에이전트 응답 1분 이내**: 기존 시간, 질문 사례, 평균/상한/p95 등 측정 기준, 사용 인원, Skills·MCP로 바꾼 처리 방식을 알려주세요. 확인 전까지 시간 수치는 제외했습니다.

## 프로필 및 증빙

- 학교명과 학과의 공식 표기. 현재는 기존의 `경제학 학사 졸업`을 유지했습니다.
- react-native-naver-login 기여 PR 링크와 구체적으로 수정한 문제. 현재 저장소 링크를 유지했습니다.
- 디몬스터의 공개 가능한 대표 앱 이름·링크와 담당 기능. `4~5개` 대신 `여러 프로젝트`로 정리했습니다.
- 지원 공고가 있으면 전달해주세요. 현재는 RN 개발·운영 경험을 중심으로 구성했으며 특정 공고와의 적합성을 단정하지 않았습니다.
